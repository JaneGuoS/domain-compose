Domain Services
Service Coordinates Cross-aggregate rule it enforces
ContentPermissionService ItemEntity · FolderEntity · UMS Permission checks span both item and its containing folder — neither aggregate alone can evaluate inherited permissions
PublishEligibilityService ItemEntity · PublishJobEntity An item can only be published if it is Active AND no conflicting publish job is already scheduled — cross-aggregate invariant
ContentSearchSyncService ItemEntity · SearchProducer After any item state change that affects discoverability, a search.ingest event must be published — decoupled from aggregate
ExternalSyncDomainService ExternalSyncTaskEntity · ItemEntity Items created by sync tasks must be associated with their source provider — ExternalSyncTask owns the task, ItemEntity owns the resulting content

DDD Gap Analysis
# Violation File(s) Severity Category
1 Anemic domain model — ItemModel has no invariant methods. Status transitions (draft→active→published→expired) are set as raw property assignments in orchestrators and writers rather than enforced aggregate command methods. ItemModel.cs · FileWriter.cs · IPublishOrchestrator impls P0 Anemic model
2 Business logic concentrated in 45+ Orchestrators instead of aggregates. IPublishOrchestrator, IPermissionOrchestrator, IFileOrchestrator etc. each contain domain rules (state guards, invariant checks) that belong inside aggregate command methods. Seismic.ContentManager.Express.Orchestrator/* P0 Layer violation
3 Reader/Writer pattern bypasses domain entirely. FileWriter.AddFile() and FileWriter.DeleteFile() call repositories directly without loading or mutating a domain entity, making invariants impossible to enforce at the domain layer. FileWriter.cs · CommentWriter.cs · FolderWriter.cs P0 Layer violation
4 Primitive obsession — no value objects for status, origin, or checkout state. ContentEventTypeEnum and item status are raw strings/enums on the model. Validation and transition rules are duplicated across orchestrators. ItemModel.cs · ContentEventTypeEnum.cs · various orchestrators P1 Missing concept
5 Permission logic scattered across all layers. Permission checks appear in controllers (route guards), orchestrators (IPermissionOrchestrator, IPermissionCheckerOrchestrator), and repositories — no single authoritative permission enforcement point. PermissionController.cs · IPermissionOrchestrator.cs · ContentPermissionRepository.cs P1 Layer violation
6 No domain events raised for key state changes. When an item is published or quarantined, the Kafka event is published directly from orchestrators/writers without first raising an internal domain event — bypassing any domain event handlers. SearchProducer.cs · ContentEventConsumer.cs · FileWriter.cs P1 Missing concept
7 Complex query logic duplicated across Readers and Repositories. ItemReader, FileVersionReader, and ItemRepository each implement overlapping query logic without a shared Specification pattern. FileVersionReader.cs · ItemRepository.cs · FolderRepository.cs P2 Infra coupling
8 Exception class hierarchy instead of typed exception enum. ContentManagerException subclasses (ContentDeleteException, NoPermissionException, etc.) are scattered — no central DomainExceptionType enum mapping to HTTP status codes. LibraryService.Core/Exceptions/*.cs P2 Missing concept

// ItemEntity.cs — invariant enforced by aggregate
public void Publish(Guid actorId)
{
    if (Status != ItemStatus.Active)
        throw new ContentManagerException(
            ContentManagerExceptionType.ItemNotPublishable,
            "Only active items can be published.");
    Status = ItemStatus.Published;
    PublishedAt = DateTime.UtcNow;
    AddDomainEvent(new ItemPublished(Id, actorId));
}

// ItemAppService.cs — orchestration only
var item = await _itemRepository.GetAsync(itemId);

// domain event handler dispatches Kafka publish

public static ItemEntity Create(

{

public async Task PublishAsync(Guid actorId, Guid itemId)
{
    // Guard: permission check via domain service
    await _permissionService.AssertCanPublishAsync(
        actorId, itemId);

    // Guard: cross-aggregate eligibility via domain service
    await _publishEligibilityService
        .AssertEligibleAsync(itemId);

    await _itemRepository.UpdateAsync(item);

Observable Truths (Post-Refactor)

What must be TRUE for this refactor to be complete — without changing external behavior:

  • ✓All item status transitions (draft→active→published→expired→quarantined) enforce invariants inside ItemEntity command methods
  • ✓FileWriter and CommentWriter classes are removed — mutations go through aggregate commands only
  • ✓AppService methods contain only orchestration: load → guard → mutate → persist → dispatch
  • ✓Orchestrators (IPublishOrchestrator, IFileOrchestrator, etc.) contain no domain rules — thin coordination only
  • ✓Kafka publish (content-event, search.ingest) is triggered by domain event handlers — not called directly from writers
  • ✓ContentManagerException is thrown only from the domain layer; HTTP status codes are resolved at the presentation layer
  • ✓All public API route paths, request shapes, and response shapes remain unchanged
  • ✓Permission checks are consolidated in ContentPermissionService — no duplicate permission logic in controllers or repositories
